# ETN RAPIRA ONLINE — Bothost + Netlify + Telegram PTS

## Что входит
- `bot.py` — Telegram-бот с командами `/start` и `/pts`, открывающими Mini App.
- `server.py` — Flask API, Telegram Mini App auth, серверный список PTS и API правил/расчёта кланового рейтинга.
- `pts.py` — расчёты индивидуального PTS, коэффициентов турниров, очков за места и таблицы стадий из `Рейтинг ETN.docx`.
- `web/index.html` — существующий интерфейс ETN с выбором тира, команды игрока и MVP при отправке матча.
- `netlify.toml` — публикация статического фронтенда и проксирование `/api/*` на Bothost.

## PTS: что считается
### Индивидуальный PTS за каждый подтверждённый турнирный матч
`(база победы/поражения по T1–T5 + убийства × 1 + ассисты × 0,5) × 1,1, если игрок MVP матча`.

| Тир | Победа | Поражение |
|---|---:|---:|
| T5 | 1 | 0 |
| T4 | 2 | 1 |
| T3 | 5 | 1 |
| T2 | 10 | 2 |
| T1 | 25 | 5 |

PTS выдаётся только после одобрения заявки со скриншотами и только для типа «Турнирный матч». Праки и товарищеские матчи PTS не начисляют. В форме нужно указать команду каждого игрока, чтобы определить победу/поражение.

### Рейтинг клана
Реализованы функции расчёта: `(очки за место + очки за стадии) × коэффициент турнира^1,6`. API `GET /api/pts/rules` возвращает таблицы правил, а `POST /api/pts/clan-calculate` рассчитывает клановые очки по призовому фонду, месту и сумме очков стадий. Это API-калькулятор и пока не сохраняет рейтинг клана в базе.

Коэффициенты из документа: 0–5 000 ₽ → 0,55; 5 000–20 000 ₽ → 0,6; 20 000–50 000 ₽ → 1,15; 50 000–150 000 ₽ → 1,6; от 500 000 ₽ → 3,0. В исходном документе не указан коэффициент для 150 000–500 000 ₽, поэтому расчёт для этой суммы вернёт ошибку, а не выдумает правило.

## Развёртывание Bothost
1. Загрузите этот архив в Git-репозиторий и подключите его к Bothost.
2. Для API/web service команда запуска: `gunicorn --bind 0.0.0.0:$PORT server:app`.
3. Для отдельного долгоживущего Telegram worker запустите `python bot.py`.
4. В обоих сервисах задайте `BOT_TOKEN` (токен от BotFather). В Telegram worker задайте `WEBAPP_URL` — публичный HTTPS URL приложения.
5. Для постоянной базы задайте `ETN_DB_PATH` на путь постоянного диска, доступный вашему тарифу. Не полагайтесь на временную файловую систему контейнера.
6. Проверка: `https://ВАШ-ДОМЕН/api/health` и `https://ВАШ-ДОМЕН/api/pts/rules`.

Не запускайте два экземпляра polling-бота одновременно с одним токеном.

## Развёртывание Netlify
1. Загрузите папку `web/` как publish directory (`web`). `netlify.toml` уже задаёт `publish = "web"`.
2. В `netlify.toml` проверьте домен в redirect `/api/*`: он должен указывать на ваш действующий домен API на Bothost. Если домен другой — замените адрес в `to = "https://.../api/:splat"`.
3. В Telegram настройте `WEBAPP_URL` на HTTPS-адрес Netlify (или на Bothost, если сайт обслуживается напрямую Flask).
4. `BOT_TOKEN` задавайте только в переменных окружения Bothost, никогда не в HTML, Netlify-коде или публичном Git-репозитории.

## Важные ограничения текущего проекта
- Форма матча и часть административных функций старого интерфейса всё ещё используют `localStorage` браузера. Серверный leaderboard строится только из данных, которые были сохранены в серверном `user_state`; одобрение локальной заявки в браузере само по себе не синхронизирует её в базу.
- Клановые очки сейчас доступны как расчётная функция/API, но нет завершённого серверного процесса подтверждения результатов турниров и сохранения рейтинга кланов.
- Текущая локальная модерация матча не является защищённой серверной админ-модерацией. Перед публичным соревновательным запуском нужно перенести заявки, модерацию, BAN и результаты турниров на сервер и разграничить права администраторов.

## Проверки
- `GET /api/health`
- `GET /api/pts/rules`
- `POST /api/pts/clan-calculate` (требует валидный Telegram Mini App initData; JSON: `{"prize_pool": 10000, "place": 1, "stage_pts": 25}`)
- `/pts` в Telegram открывает Mini App с рейтингом.
